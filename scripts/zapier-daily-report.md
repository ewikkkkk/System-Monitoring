# Send saved System Monitoring reports with Zapier

Use this as the report source in the AI Automation project's weekday Teams Zap. Import the Excel export and save the report in System Monitoring before the Zap runs. The feed returns the latest saved version for the current Asia/Manila date, ordered by as-of time and then version ID.

1. Keep the existing **Schedule by Zapier → Every Day** trigger. Set the account time zone to Asia/Manila and schedule the run after the Excel import.
2. In place of reading Google Sheets and running `process-report.js`, add **Webhooks by Zapier → GET**. Use the System Monitoring host's approved HTTPS address with `/api/system-monitoring/ticket-reports/zapier/daily`. Set the `Authorization` header to `Bearer <host-issued service token>`. The host must validate the token and grant the service account access to this endpoint only. Use host-managed OAuth via API by Zapier if the token requires interactive renewal.
3. Add a filter that continues only when `ready` is true. If there is no saved report for today, the response is `{"ready":false,"report_date":"YYYY-MM-DD","part_count":0}`. A missing report does not fall back to a prior day. If you want a missing-report alert, branch on `ready=false` before the send paths.
4. Use AI Automation's updated `send-multipart.js` for both single and multiple messages. Paste it inside the Code by Zapier SDK main function, map `messages_json` and `report_date` from the GET response, and bind the approved Teams connection as `teams_reporting`. Supply either `chat_id` or both `team_id` and `channel_id`. The feed includes clickable Help Desk ticket links and assignee names. For a single channel post, the native Teams action can also use `message_html` with HTML format.
5. Run the Zap once against a test Teams destination with a saved test report. Verify the counts and links, then test the skip path on a day without a saved report. Enable only one report source for the destination. Before replaying a run, check Teams, particularly if some parts posted. The read endpoint does not record Teams receipts or deduplicate manual reruns.

Zapier cannot reach `127.0.0.1`. Use a deployed host endpoint that Zapier is authorized to reach. Local demo testing verifies the feed without posting to Teams. The GET action, its authorization and the schedule are configured in the [Zapier webhook editor](https://help.zapier.com/hc/en-us/articles/8496326446989-Send-webhooks-in-Zaps) and [Zapier schedule settings](https://help.zapier.com/hc/en-us/articles/8496288648461-Schedule-Zaps-to-run-at-specific-intervals).
