## 5. Which routes must be restricted, and to whom?

GET /permissions: authenticated monitoring viewers. Host router-level policy must grant req.monitoringPermissions.canManageDeploymentDates only to administrators authorized to schedule deployment dates. POST /tasks and PUT /tasks/:id carrying targetDeploymentDate require that capability in addition to normal task-write access. Other developers/testers can view dates and edit their permitted task fields without changing scheduling.
All /api/system-monitoring routes require authenticated monitoring-team access at router level. GET /tasks, GET /my-tasks, GET /people, GET /tasks/:id/history, GET /tasks/:id/comments, GET /deployments, GET /bug-occurrences, GET /task-resolutions, GET /task-timeline: authorized monitoring viewers. POST /tasks, PUT /tasks/:id, PATCH /tasks/:id/status, POST /tasks/:id/occurrences: developers, testers, and team leads. POST /deployments (Deployment/Fix/Revert): release managers and team leads. Apply method-level policy in host router middleware. No client identity or local authorization tables are accepted.

GET /vouchers, GET /vouchers/:id/history, POST /vouchers, POST /vouchers/import, POST /vouchers/:id/use and POST /vouchers/:id/restore: authorized Infra staff and Infra team leads only. Voucher codes may grant network access; general task viewers must not inherit access to these endpoints. The host owns all router-level authorization. Process engineer task access must also be granted by the host according to company policy.

GET /ticket-reports and GET /ticket-reports/:id: authenticated Help Desk monitoring viewers/team leads. POST /ticket-reports: authorized Help Desk reporters/team leads. The host must enforce this method-level policy at router level; general task viewers must not automatically inherit Help Desk report access. No edits/deletes or AI routes are exposed.

GET /ticket-reports/:id/teams, POST /ticket-reports/:id/teams/preview and POST /ticket-reports/:id/teams/send: authorized Help Desk reporters/team leads with permission to disclose that report to the approved Teams group. The host must enforce this at router level and provide each actor's delegated Microsoft 365 connection. Send posts a real external message and mentions group members; viewing a report must never trigger it.
