## 1. Which database, and which schema/tables does it read and write?
Production database name is not supplied yet. Use the METS Hub application database; apply numbered migrations 001–013 in order with a migration ledger owned by the host. Schema: monitoring. Reads People, Tasks, TaskHistory, Deployments, Vouchers, VoucherHistory, BugOccurrences, TicketReports, TeamsDeliveries; inserts/updates Tasks, Vouchers and TeamsDeliveries; inserts TaskHistory, Deployments, VoucherHistory, BugOccurrences and TicketReports. Migration 005 adds the production event log; 006 and 007 add voucher inventory and history; 008 adds nullable JSON attempt details to VoucherHistory; 009 adds Tasks.relatedTickets; 010 adds BugOccurrences; 011 adds Tasks.moduleName without remapping existing system values. SQL Server 2016+ with database compatibility level 130+ is required for OPENJSON/ISJSON. People must be provisioned from the host directory by an operator. SQL mode inserts no sample people, tickets or vouchers. Explicit local demo mode uses `.local/monitoring-demo.json` (people/tasks/history/deployments/vouchers/voucherHistory/bugOccurrences/ticketReports/teamsDeliveries collections), a file-backed JSON database; no SQL tables are touched in demo mode. Voucher collections are initialized lazily without replacing existing demo data.

## 5. Which routes must be restricted, and to whom?
All /api/system-monitoring routes require authenticated monitoring-team access at router level. GET /tasks, GET /people, GET /tasks/:id/history, GET /deployments, GET /bug-occurrences, GET /task-resolutions: authorized monitoring viewers. POST /tasks, PUT /tasks/:id, PATCH /tasks/:id/status, POST /tasks/:id/occurrences: developers, testers, and team leads. POST /deployments (Deployment/Fix/Revert): release managers and team leads. Apply method-level policy in host router middleware. No client identity or local authorization tables are accepted.

GET /vouchers, GET /vouchers/:id/history, POST /vouchers, POST /vouchers/import, POST /vouchers/:id/use and POST /vouchers/:id/restore: authorized Infra staff and Infra team leads only. Voucher codes may grant network access; general task viewers must not inherit access to these endpoints. The host owns all router-level authorization. Process engineer task access must also be granted by the host according to company policy.

GET /ticket-reports and GET /ticket-reports/:id: authenticated Help Desk monitoring viewers/team leads. POST /ticket-reports: authorized Help Desk reporters/team leads. The host must enforce this method-level policy at router level; general task viewers must not automatically inherit Help Desk report access. No edits/deletes or AI routes are exposed.

GET /ticket-reports/:id/teams, POST /ticket-reports/:id/teams/preview and POST /ticket-reports/:id/teams/send: authorized Help Desk reporters/team leads with permission to disclose that report to the approved Teams group. The host must enforce this at router level and provide each actor's delegated Microsoft 365 connection. Send posts a real external message and mentions group members; viewing a report must never trigger it.
