# System Monitoring

## Daily Help Desk reports

### Send to a Teams group with real mentions

For a temporary local connection, sign into [Microsoft Graph Explorer](https://developer.microsoft.com/en-us/graph/graph-explorer) with your work account. In **Consent to permissions** approve the delegated `Chat.ReadBasic` and `ChatMessage.Send` permissions, subject to your organization's policy. Copy the **Access token** yourself. In a local PowerShell 7 terminal at the project root, run `npm run teams:test`. The launcher asks for a group-chat link/ID, group name, and the token in a hidden prompt. Do not paste the token in chat. It starts the demo with process-local credentials, replacing a recognized demo server on the selected port; it does not save the token to a file or command-line argument. The token is held in the running server's environment until it stops and must be refreshed after expiry. No message is sent by this launcher. **Prepare mentions** performs the actual Microsoft/group check; only the final Send button posts the report. Use a test group containing the report's assignees, or import a small test export assigned to members of that group. If your tenant blocks consent, ask your Microsoft 365 admin rather than broadening permissions.

Save or open a daily report, select **Send to Teams**, choose an approved group, then select **Prepare mentions**. The dialog shows the report, destination and every matched/unmatched assignee. **Send report** remains disabled until all unfinished-ticket assignees match group members. Sending uses real Graph mention entities; the normal clipboard copy does not create notification mentions. Each Microsoft 365 user is mentioned once across all status sections. Microsoft must return a message receipt before the UI reports a verified send.

The current local demo has **no Teams connection configured**. No real message or notification has been sent. A group name alone is insufficient: the host needs its actual chat ID and a delegated work-account connection with `Chat.ReadBasic` and `ChatMessage.Send`. The account must have access to the group. Do not use application-only migration permissions for routine sends. See [send chat messages](https://learn.microsoft.com/en-us/graph/api/chat-post-messages?view=graph-rest-1.0) and [read chat members](https://learn.microsoft.com/en-us/graph/api/chat-list-members?view=graph-rest-1.0).

Supply `getAccessToken(actorId)`, approved `destinations` containing `id`, `name`, `chatId`, optional `aliases` mapping Excel assignee names to their Microsoft 365 email/Entra user IDs, and `resolveTicketUrl(reference)`. The host owns OAuth, consent and token refresh; the router factory remains `createSystemMonitoringRouter(getPool)`. Tokens stay on the server. The service verifies the destination's group type and members before preparing a message, and uses the actual group topic when available.

Local-only setup: provide `TEAMS_CHAT_ID`, `TEAMS_CHAT_NAME`, and `TEAMS_GRAPH_ACCESS_TOKEN` through your local process environment, then restart the demo server. Never commit or paste tokens into chat. The short-lived delegated token must come from your organization's approved Microsoft authentication flow. If export and Microsoft display names differ, create `.local/teams-assignees.json` with an object mapping each export name to its actual member email or Entra user ID. Exact unique display-name matches work without aliases. Local configuration is throwaway; integration must use the host's per-user token getter.

Apply migration **013** after 012. Grant the app login SELECT/INSERT/UPDATE on `monitoring.TeamsDeliveries`. The host restricts Teams status, prepare and send routes to authorized Help Desk reporters/team leads. A database reservation prevents duplicate/concurrent sends to the same group for a saved report version. Known rejected requests can be deliberately retried. A timeout or uncertain receipt is not treated as success and is not retried automatically: check the group before an operator reconciles the reservation. There is no reconciliation UI yet. Message receipt and SQL logging cannot be committed atomically. Payloads over the conservative 80 KB budget are blocked without omitting tickets. This implementation supports group chats; channels, scheduling and automatic sending are outside the current scope.

Open **Daily reports** in the sidebar. Choose **Import Excel** and select the Help Desk `.xlsx` export, then choose its worksheet. Required headers are `Ticket ID`, `Subject`, `Status`, and `Assigned To` or `Agent`. `Assigned To` wins when both assignee columns have values. Optional `Due by Time` supplies deadlines. The reader accepts at most 10 MB, 5,000 tickets and 200 columns; it rejects duplicate ticket IDs, incomplete rows, invalid deadlines and formulas in report fields rather than silently changing the totals.

Set the reporting date, as-of time and the time zone used by the exported timestamps. For the supplied example use October 23, 2026 at 14:20. Click **Generate report**, review the status sections grouped by assignee, then **Save daily report**. **Copy for Teams** copies formatted HTML and plain text. If rich copy is unavailable, the UI falls back to plain text or shows selectable report text. It never posts a Teams message. Real Teams paste behavior has not been verified.

Ticket links require the actual Help Desk URL. In the optional link-template field replace the ticket identifier in that URL with `{ticket}`. URL construction stays in `src/services/api.js`. If no template is supplied, the report shows ticket numbers as plain text and explains the missing links. The supplied workbook has no embedded ticket hyperlinks. No URL or Help Desk connection is guessed.

The generator is coded and requires no AI subscription, API key or network model call. It reproduces Open, Waiting on Customer, Pending and Internal sections and preserves additional unfinished statuses. Closed and Resolved contribute to imported totals but do not appear in unfinished detail. Overdue counts only Open and Waiting on Customer deadlines strictly before the report as-of time. Pending and Internal are excluded. Excel deadlines are interpreted as wall-clock times in the selected export time zone. A report is a snapshot of the imported statuses; backdating does not reconstruct historical ticket states.

**Report history** retains each saved version with source file/sheet, author and save time. Daily totals use the latest as-of report per day, then the latest saved ID for a tie. Revisions are not added together. Days without an import have no data, and totals represent snapshots rather than newly created tickets. The chart shows the last 30 saved days; the dated rows retain all saved days. Saving/retrying the same request is idempotent. There is no edit/delete, automatic import or scheduled reporting job.
