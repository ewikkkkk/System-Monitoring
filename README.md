# System Monitoring

React 18 JSX page and Express 5 module for enhancement, bug and Infra voucher tracking. Requires Node 20.19+; SQL mode requires SQL Server 2016+ with compatibility level 130+. SQL mode has no seeded or simulated records.

## Local demo (no SQL Server needed)

Run `npm ci` once, then `npm run demo`. Open http://127.0.0.1:5173. Stop an existing local server first if port 5173 is busy. Demo mode includes four fictional people and six sample tasks across all statuses. Create tasks, assign people, change status, add notes, filter the register, and inspect history. Records persist across reloads and server restarts in `.local/monitoring-demo.json`, an ignored JSON file database. It is not SQL Server or a substitute for SQL Server acceptance. No additional dependencies or credentials are needed. The demo adapter is local-only and never imported by the production router; discard `server/demo/` together with `server/dev-server.js` on integration. To return to SQL mode, stop the demo and run `npm run dev` with your SQL settings. Demo records are not automatically transferred to SQL Server.

Run `npm install`, configure SQL_SERVER, SQL_DATABASE, SQL_USER, SQL_PASSWORD and DEV_USER_ID in the process environment, apply db/migrations/001–011 to the selected application database, then run `npm run dev`. Optional SQL_TRUST_CERTIFICATE is for trusted local development certificates only. Open http://127.0.0.1:5173. `npm run build` builds the development frontend.

Migrations are operator-applied, once, in numeric order. The database name remains a deployment choice. Provision monitoring.People with real hub user IDs, display names and assignment roles (developer, tester, both). Assignment roles are directory metadata, never access-control roles.

Voucher monitoring is available under Infra operations. Add voucher requires a code and a Bancal 1/Bancal 2 location tag; saved vouchers enter Active inventory. Use captures the Help Desk ticket reference, local date/time, person involved, client, device, purpose and duration. Matching successful use yields Used. A different requested location records a mismatch and keeps the voucher Active for its tagged location; subsequent use preserves the earlier attempt's metadata in history. Matching manual invalidation yields Invalid. Existing Invalid location-mismatch records have a Return to active icon and require an operator reason. Used and other Invalid records cannot be restored. This records inventory and usage only; it does not issue network access, validate against network equipment or connect to Help Desk/METS One. Ticket links use the existing Help Desk placeholder. Future task-to-METS One to-do synchronization still needs host APIs and user mapping.
