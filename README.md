# System Monitoring

React 18 JSX page and Express 5 module for enhancement and bug tracking. SQL mode has no seeded or simulated records.

## Local demo (no SQL Server needed)

Run `npm ci` once, then `npm run demo`. Open http://127.0.0.1:5173. Stop an existing local server first if port 5173 is busy. Demo mode includes four fictional people and six sample tasks across all statuses. Create tasks, assign people, change status, add notes, filter the register, and inspect history. Records persist across reloads and server restarts in `.local/monitoring-demo.json`, an ignored JSON file database. It is not SQL Server or a substitute for SQL Server acceptance. No additional dependencies or credentials are needed. The demo adapter is local-only and never imported by the production router; discard `server/demo/` together with `server/dev-server.js` on integration. To return to SQL mode, stop the demo and run `npm run dev` with your SQL settings. Demo records are not automatically transferred to SQL Server.

Run `npm install`, configure SQL_SERVER, SQL_DATABASE, SQL_USER, SQL_PASSWORD and DEV_USER_ID in the process environment, apply db/migrations/001–005 to the selected application database, then run `npm run dev`. Optional SQL_TRUST_CERTIFICATE is for trusted local development certificates only. Open http://127.0.0.1:5173. `npm run build` builds the development frontend.

Migrations are operator-applied, once, in numeric order. The database name remains a deployment choice. Provision monitoring.People with real hub user IDs, display names and assignment roles (developer, tester, both). Assignment roles are directory metadata, never access-control roles.

Integration: mount `createSystemMonitoringRouter(() => pool)` from server/index.js at `/api/system-monitoring` after the hub authentication/authorization middleware. Import the default page from src/SystemMonitoringPage.jsx with `{ darkMode, onToggleDarkMode, onToggleSidebar }`. The page uses the host theme callback for its requested module theme switch. Call configureMonitoringAuth from src/services/api.js with an async bearer token getter. Copy server/db/pool.js, the shared/ task-number helper directory, and the numbered SQL migrations. Discard server/dev-server.js, src/dev.jsx, and index.html. The SQL seam uses AsyncLocalStorage to keep pool getters isolated between concurrent mounts. There is no auth provider, shell, or AI integration.
